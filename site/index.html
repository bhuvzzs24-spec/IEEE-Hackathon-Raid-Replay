The gap

Ten sports have a data plugin. Kabaddi had a news label.

IPTC Sport Schema is the open, RDF-based sports-data standard from the news-standards body IPTC. Its ontology ships statistics plugins for ten sports. In every IPTC standard, kabaddi existed only as a topic tag for news stories — medtop:20000978 — with no way to say who raided, who tackled, or how a point was scored.

Closed by design

Sport Schema only accepts pre-approved properties on a play. Golf got in by being added to that list. So a kabaddi plugin has to extend the allowed list — not just invent new words.

Our plugin

A small Turtle ontology (raid, card, review, substitution + 40 properties + 4 code lists) and SHACL shapes that extend IPTC's closed shapes and encode the rules of the game.

Lossless, provably

Five simulated matches go JSON → Turtle / JSON-LD → JSON with zero differences, pass IPTC's own validator, and fail it without our plugin.

How it works

One raid, three formats, zero loss.

Our simulator writes native kabaddi JSON. The converter (Python + rdflib) maps every field to Sport Schema and back. pySHACL checks the result against IPTC's shapes plus ours.

Proof

Zero differences. Every file valid. And it isn't a fake pass.

All numbers below are computed by our test suite (pytest) and proof script from the files in data/.

≠ The diff catches every corruption

We break the converted final on purpose and convert it back. DeepDiff must report a difference.

    ✕ The validator rejects bad kabaddi

    Each corruption must fail SHACL validation, with a message saying why.

      🔒 Without our plugin, IPTC's own checker rejects every file

      IPTC's shapes are closed. Remove the kabaddi plugin and every one of the 10 files fails.

      Bugs we found in the standard

      IPTC's files didn't load as shipped. We patched them in a few lines — in memory, never on disk.

      We use the official files from IPTC's GitHub repository (Sport Schema 1.1). These are the problems we hit, and our workaround for each (iptc/loader.py).

      01

      Missing full stop in vocabulary files

      15 of 17 NewsCodes vocabulary files end an @prefix line without the terminating “.”, so no strict Turtle parser can read them.

      @prefix spct:	<…/newscodes/spct/>. ← this full stop is missing

      Fix: one regex adds the “ .” on load.

      02

      Shapes only Apache Jena tolerates

      6 shapes use sh:ignoredProperties without sh:closed true. The SHACL spec forbids that; Jena ignores it, pySHACL refuses to load the shapes at all.

      sport:CompetitionShape
  # sh:closed true;
  sh:ignoredProperties ( rdf:type rdfs:label ) ;

      Fix: drop sh:ignoredProperties on non-closed shapes (it has no effect there).

      03

      Shapes that are referenced but never defined

      sh:node points at 4 shapes that don't exist, e.g. NewsCodesSportEventStatusShape. Any event with a status fails to validate.

      Fix: define the four missing shapes, modelled on their siblings.

      04

      A one-letter SKOS typo

      The vocabularies use skos:HasTopConcept (228 times). The SKOS property is skos:hasTopConcept, so tools never see the top concepts.

      Fix: add the correctly-cased triple alongside each one.

      05

      A validator built around one data file

      IPTC's script cats the ontology, all vocabularies and the data into one temporary file, because Jena's shacl tool accepts a single data file.

      Fix: merge the graphs in Python and call pySHACL directly.

      06

      Numbers typed as strings

      IPTC's shapes require xsd:string for sport:score, sport:sequenceNumber and sport:uniformNumberEvent — the exact 2 vs “2” trap.

      Fix: we obey IPTC's shapes and convert those three back to integers through an explicit table; every kabaddi number is a real xsd:integer.
